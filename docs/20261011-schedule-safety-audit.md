# 좋은일자리 일정관리 안전성 점검 및 수정 기록 (2026-10-11)

## 수정 배경
- GitHub `my-html-9/main/index.html` 원본은 유지하고 이 브랜치에서 작업.
- 기존 상담일지 `my-html-4` 최신 본문은 GitHub 연결의 파일 크기 제한으로 미확보. 구버전 v121으로부터 최신 계산식에 대한 확정적 주장을 하지 않음.
- 2027년 공휴일 출처: 2027년 월력요항 (우주항공청 2026-06-29 발표); 한국천문연구원 천문우주포털 2027 달력자료. 추후 임시공휴일은 재확인 필요.

## 브랜치에서 수정한 내용
1. 빠른 상담 예약: 남은 빈 시간 0건일 때 이미 예약된 시간 목록을 재표시하지 않음.
2. 상담 추가·수정: 같은 상담사에게 겹치는 시간이 있으면 중복 상담 등록을 막음. 근무 일정 겹침은 기존 사용자 확인 방식 유지.
3. 2027년 휴일 24개 표시 및 비근무일 판정 반영.
4. 미전송 로컬 초안 안전복원: 서버 기록 전체 교체 금지. 초안에만 있는 신규 ID 추가, 동일 ID 불일치는 서버 우선으로 보존하고 로컬 충돌 백업에 기록. **기존 초안의 수정/삭제는 자동 복구하지 않음**.
5. SQL 배포기록 및 되돌리기용 기존 함수 정의를 `docs/sql/`에 보관.

## 실제 서버 반영 (Supabase '좋은일자리-상담일정관리')

## 자동 실행·정적 검증
- 패치된 HTML의 인라인 자바스크립트 2개 구문 검사 통과.
- 빠른 예약 시뮬레이션: 2칸 모두 차 있을 때 '예약 가능한 시간 없음', 한 칸만 빈 경우 그 시각만 표출 → 통과.
- 로컬 복구 충돌 테스트: 서버의 A/B 보호, 초안 신규 C만 추가, 기존 A의 다른 값은 덮어쓰지 않음 → 통과.
- DB 소스 검증: 4개 서버 함수가 `schedule_business_holidays`를 참조하고 고정 2026 문자열 비교 제거 → 통과.

## 남은 중요 검증
- **일반 본인 일정 동시 저장은 현재 `upsert`와 삭제 차집합 방식임.** 교차 기기 동시수정 시 원자적 충돌 해결/낙관적 잠금이 없으므로 서버 재설계 필요.
- `schedule_work_report`: 같은 직원·날짜·유형 등록 2건이 그룹 합산 1건으로 표시될 수 있음. 사용자 화면에 '실제 등록 건수' vs '유형·날짜별 건수' 구분 필요.
- 실제 직원 계정 예약, iPhone PWA, 푸시 알림, 외부 캘린더, 브라우저 인쇄 테스트 필요.
- 최신 상담일지 통합본 `my-html-4`의 IAP/훈련일수/수당 계산은 **미점검**이며, 법령 API 접근성과 조문 버전 매칭 역시 최신본으로 확인 필요.
- 새 휴일 데이터 반영은 연간 관리 절차를 마련해야 하며, 2028년 이상 예약은 행정자료 입력 전 제한됨.

5. 서버 함수 권한: 로그인 계정에서 본인/동지사만, 비인가·익명에서 호출 거부.

## 추가 점검 및 수정 (2026-10-11, 계속)
- 복구 초안 v2는 기존 서버 스냅샷의 ID 목록 `baseIds`를 함께 보관. 다른 기기에서 삭제한 기존 ID는 신규 일정으로 오판하지 않음. 구형 초안처럼 기준 스냅샷이 없는 경우 자동 추가하지 않고 충돌용 로컬 백업에 보존.
- 비동기 서버 저장이 진행되는 동안 새로 수정한 데이터가 저장 완료로 잘못 표시되던 경로를 수정. 업로드 시작 당시의 불변 스냅샷을 기록하고, 중간 변경은 다음 업로드 대상으로 남김.
- 위 두 항목에 대해 미전송 데이터/삭제된 항목 보호 및 저장 중 변경 시뮬레이션 통과. 실사용 계정·다중기기 통합 테스트는 별도 필요.
- 추가 서버 확인: `schedule_work_report`에 실제 등록건수 필드(`actualLeaveEntries`, `actualExternalEntries`)가 있으며, 검수 브랜치 화면은 해당 필드를 표시함. 일부 지사별 표는 여전히 날짜·유형 요약 집계.
- 2026년 공휴일 데이터 중 5월 1일과 7월 17일 누락분을 추가.
- 서버 `schedule_events`에는 `id` 기본키와 직원·날짜 일반 인덱스만 있고, **시간 겹침을 차단하는 DB 트리거·고유 제약은 미적용**. 동시에 두 창에서 저장하거나 교차 기기 갱신하는 경우는 여전히 운영 위험. `docs/sql/20261011_schedule_prevent_overlap_review_only.sql`는 검토용으로만 유지하고 **운영 적용하지 않음**.
- GitHub 검수 브랜치와 운영 `main`은 분리 유지. 브라우저/모바일/푸시/인쇄 검증 전 무조건 병합 금지.


## 추가 검수 / 초안 덮어쓰기 보호 (2026-10-11, 이어받은 작업)
- 이전 미전송 초안이 존재하지만 사용자가 복원을 **취소한 경우**, 다음 로컬 변경이 동일 저장키를 덮기 전에 기존 초안을 `schedule_deferred_draft_backup_<직원ID>_<시각>`에 복제하고 **동일 내용 재조회 검증**을 수행.
- 공간 부족·브라우저 저장소 오류 등으로 별도 보관이 실패하면 원본 미전송 초안을 보존하고 후속 서버 자동 전송을 차단. UI에 JSON 내보내기 및 저장공간 점검 안내. 이후 재수정 시 보관 재시도 가능.
- 평상시 로컬 초안 쓰기도 저장 직후 내용 확인. 쓰기 실패 시 정상 저장으로 표시하지 않고 새로고침 금지/재시도 경고.
- 서버의 다른 기기 버전 충돌과 **기기 백업 실패**가 동시에 발생하면, 자동 재시도·화면 새로고침에 의한 소실을 막도록 차단 상태 유지.
- 실제 검수 브랜치 HTML 인라인 JS 2개 `new Function` 파서 검사 통과. 브라우저 API를 흉내 낸 로컬 저장 회귀 테스트 4사례 통과 (일반 저장, 복원보류 후 별도보관 성공, 별도보관 실패 시 기존 초안 유지/전송 차단, 기기 저장 실패 경고).
- 새 변경 커밋: `2202af9cb9a553f9383ce84bd229c0e75aa6af73`.
- Supabase 운영 DB 읽기 전용 점검: `schedule_apply_event_changes` 및 `schedule_get_snapshot`은 `authenticated` 실행 허용, 내부 `schedule_get_snapshot_v17`은 공개 실행 불허이나 인증된 보안 정의자 wrapper를 경유함. `schedule_enforce_consultation_overlap_trg`는 **현재 활성화**되어 있음. 기존 기록의 '트리거 미적용'은 이전 시점의 상태이므로 현 상태와 구별할 것.

### 운영 반영 전 남은 확인 (중요)
1. 실제 직원 계정 2개, 서로 다른 PC/휴대폰에서 동시 입력·수정·삭제 테스트 후 최신 값 보존 확인. 운영 참여자 자료가 아닌 테스트용 일정 사용.
2. 공유 휴무·공통 행사·참여자 목록은 아직 이벤트 RPC와 동일한 원자적 버전 검사를 갖추지 못함. 고위험 다중기기 편집에 대한 별도 데이터 모델/서버 방어 필요.

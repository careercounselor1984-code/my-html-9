# 일정표 전체 점검 (2026-10-18)

## 수정한 재현 가능한 문제

1. 다른 탭/화면의 SIGNED_OUT 시 메인 일정표가 계속 이전 직원 자료를 유지하던 처리를 중앙화했다. 로그인 확인·일정 조회·다단계 저장은 계정 세대를 캡처하고, 로그아웃/재로그인 후 늦게 도착한 이전 응답과 후속 쓰기를 차단한다. 새 조회가 시작됐으면 더 오래된 조회 결과를 폐기한다. 로그아웃 시 표시 자료·열린 대화상자·보고/공유/학교 출입 목록을 정리한다. 기존 계정별 미전송 기기 백업은 삭제하지 않는다.
2. 관리자 보고·총괄·인계·공유·학교 출입·근무현황 조회에 같은 계정 세대 검사를 적용했다. 인증 오류 시 게이트로 돌아가고 일반 통신 오류는 저장/새로고침 안내로 처리한다.
3. 할 일 알림 조회/등록 완료가 계정 변경 또는 reset 뒤 이전 상태를 다시 켤 수 있던 비동기 경로에 세대 검사를 추가했다.
4. 서비스워커 업데이트가 동일 GitHub origin의 모든 캐시를 삭제하던 범위를 goodjob-schedule-*로 한정했다. 다른 통합본/앱 캐시는 보존한다. 캐시 버전을 갱신했다.
5. 통합본이 보낸 expectedName과 일정표 직원이 다른 경우 직접 예약을 차단한다. 이전 통합본 메시지는 계속 처리하지만 새 통합본은 계정 이름을 함께 보낸다.

## 검사

기존11개 및 신규2개, 로컬13개 회귀 검사: 초안 복원/삭제 부활 방지, 저장 중 변경, CAS 충돌, 월말/윤년/휴일, 내담자 상태와 훈련/지정일, 할 일 기한·일/주/월, 서버 푸시의 소유자/기기/중복/취소, 금요일 비근무, 연차·외부일정 칸, 방문자 인쇄 시 직원 일정 숨김, 직원별 알림 범위, 로그아웃/인증/조회/쓰기 지연 응답, 앱 간 캐시 격리, 알림 계정 전환을 검사한다. 누락돼 있던 client-lifecycle 검사를 CI에 포함했다.

실제 Chrome CI에 전체 일정표 시작, 개인 일/주/월·센터·연차 화면의 가상자료 렌더링, 방문자 인쇄 개인정보, 로그아웃 정리, 넓은/좁은 화면과 가로 넘침 검사를 추가했다. 내담자 관리와 할 일 화면도 모의 직원으로 실제 폼 저장·월말6회차·완료 처리·로그아웃 정리를 검사한다. 이는 운영 DB에 실제 일정을 만드는 테스트가 아니다.

## 운영 서버 읽기 전용 점검

일정표 관련29개 테이블 RLS 활성 확인. 개인 할 일/내담자 관리·알림 기기/예약의 정책은 auth.uid 소유권 및 활성 직원·비밀번호 변경 완료를 요구한다. 일정·참여자/공통 자료 저장 함수는 버전/CAS·행 단위 소유권과 역할 검사를 한다. 주요 조회·저장·예약 RPC는 익명 실행을 허용하지 않는다. 실제 비로그인 HTTP 호출에서 snapshot401, 직원 알림400(로그인 필요), 관리자 보고400(관리자만)으로 거부됨을 확인했다. 실제 직원/상담 자료를 조회하거나 수정하지 않았다.

보안 어드바이저에는 기존 익명 SECURITY DEFINER8개, 인증 사용자 SECURITY DEFINER33개, public pg_net, 유출 비밀번호 방지 비활성 경고가 남아 있다. 함수 실행 허용만으로 공개 자료 노출을 뜻하지는 않는다. 확인한 직원 알림·보고·부재 함수는 내부에서 직원/관리자 인증을 요구하며, 토큰 기반 director_morning_auth는 별도 공개 흐름이 있어 일괄 차단하지 않았다. 내부 전용 RPC의 최소 실행 권한 정리와 pg_net 이동은 호출 의존성/롤백을 따로 확인할 유지보수 항목이다. 요금제나 인증 설정을 임의 변경하지 않았다.

참고: [실행 권한 경고](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [확장 스키마 경고](https://supabase.com/docs/guides/database/database-linter?lint=0014_extension_in_public), [비밀번호 보호](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

## 실기기 확인 범위

실제 직원 두 계정의 PC/휴대폰 동시 편집, iPhone PWA와 푸시 수신, 실제 프린터 출력/카톡 이미지 붙여넣기/외부 캘린더 제공사 동기화는 자동 검사와 구분한다. 이번에는 데이터베이스 레코드·DDL·ACL·유료 설정을 변경하지 않았다.

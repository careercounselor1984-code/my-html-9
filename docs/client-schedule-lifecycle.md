# 내담자 상태와 확인용 일정

2026-10-17 구현. 이 기능은 내담자 개인 일정의 목록·집계를 정리하며 고용24의 실제 참여 상태, 상담 예약, 기존 개인 할 일 알림을 변경하지 않는다. 내담자 일정 자체에는 별도의 예약 알림 기능이 아직 없다.

## 사용

전체 내담자 → **취업·중단 처리**. 상태를 변경한 내담자는 **상태·일정 관리**로 표시한다. 날짜·정보 수정에서도 편집 화면 첫 부분의 **참여 상태 · 취업·중단 처리**를 사용할 수 있다.

2026-10-25: 목록에서 상태 처리 바로가기, 편집 화면 상단 배치, 적용일·사유 표시, 저장 전 제외/유지 건수 안내를 추가했다. 별표 일정도 상태 적용일 이후에는 기본 제외하므로 출근 확인·서류 제출 등 계속 필요한 일정은 개별 체크를 해제해 유지한다. 상태·적용일 변경 사유는 기존 변경 이력과 `statusReason`에 보관한다. 취업·일시 중지·종료 저장과 선택 유지·복구를 실제 DOM/모의 저장으로 검사한다.

- 참여 중 / 취업 / 일시 중지 / 종료·중단 상태와 적용일을 저장한다.
- 취업·일시 중지·종료는 적용일부터 일정을 기본 제외한다. 체크를 풀어 개별 일정을 유지할 수 있다.
- 이후 추가되는 일정도 해당 상태의 기본 제외 규칙을 따른다. 개별 유지·제외 선택은 날짜 변경 후에도 같은 일정에 유지한다.
- 참여 중으로 변경·일정 복구 버튼은 남은 일정 제외를 해제한다. 변경 사유를 입력하고 저장한다.
- 제외한 일정은 원본 날짜를 삭제하지 않고 목록·집계에서 제외한다. 적용일 전의 과거 일정은 보존한다.
- 재진단 지정일을 직접 입력할 수 있다. 지정일·재진단·훈련·서비스 만료를 같은 규칙으로 정리한다.
- 날짜 변경, 제외, 복구, 상태와 적용일 변경을 사유·담당자 식별자·저장 시각과 함께 이력에 남긴다.

## 저장과 검증

기존 `schedule_private_items`의 `iap` payload를 사용한다. 상태가 없는 기존 자료는 참여 중으로 취급한다. 기존 소유자 조건과 `updated_at` 비교로 동시 수정 충돌을 막는다. 훈련은 고유 ID로 식별하여 다른 훈련 추가·삭제 시 제외 대상이 뒤바뀌지 않는다. 기존 날짜와 기록을 자동 삭제하지 않는다.

DB의 payload 제한은 20,000 bytes다. 프런트는 19,500 bytes에서 저장을 막고 기존 기록을 보존한다. 장기적으로 변경 이력이 누적되면 별도 이력 테이블로 옮겨야 하며, 현재는 자동으로 과거 이력을 잘라내지 않는다.

## 후속 요구: 전산 실시간 확인과 구직인증번호 마감

사용자 요청: **나중에 실시간 전산 확인이 가능해지면 구직인증번호의 마감도 확인한다.** 현재 자동 조회 기능은 구현하지 않았다.

연동 시 필요한 사항:

1. 구직인증번호와 실제 유효·마감일을 전산의 확인 가능한 항목으로 매핑한다. 다른 서비스 만료일을 구직인증 마감일로 추정하지 않는다.
2. 마지막 확인 시각, 전산 출처, 유효·만료·확인 불가 상태를 함께 보관한다.
3. 전산 취업·종료·지정일 변경과 수기 기록이 다르면 차이를 보여주고 반영할 항목을 확인한다. 수기 기록을 무조건 덮어쓰지 않는다.
4. 마감 연장·재인증 시 이전 날짜와 이력을 남기고, 실제로 예약 알림을 제공하게 되면 이전 알림도 함께 취소·재예약한다.
5. 외부 조회 실패 시 기존 마감일을 삭제하지 않고 확인 실패를 구분한다.

단순 실시간 구독을 켠다고 고용24 전산을 조회할 수 있는 것은 아니다. 허용된 API 또는 사용자가 확인 중인 전산 화면과의 연결이 먼저 필요하다.

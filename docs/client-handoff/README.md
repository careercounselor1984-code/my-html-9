# 관리자 내담자 분할 인계 (2026-10-19)

직원 계정관리의 ‘비활성 직원의 내담자 나누어 인계하기’ 또는 내담자 일정관리의 ‘관리자 내담자 인계’에서 이용한다. 관리자·부장·팀장에게만 허용하며 팀장은 자기 센터의 출발/도착 직원만 처리한다. 일반 직원과 비활성 계정은 서버에서 차단한다.

기능을 배포해도 자료가 자동으로 옮겨지지는 않는다. 실제 자료의 인계는 실행하지 않았다. 기존 담당자가 비활성 상태이고 새 담당자는 활성·계정 연결·비밀번호 변경 완료 상태여야 한다.

## 사용하는 순서

1. 직원 계정관리에서 기존 담당자를 비활성화한다. 인계 화면은 계정을 자동으로 비활성화/재활성화하지 않는다.
2. 인계 화면에서 기존 담당자를 선택한다.
3. 내담자를 선택하고 각자 새 담당자를 지정한다. 한 번에 최대 100명이며 여러 상담사에게 나누어 배분할 수 있다.
4. 함께 옮길 향후 상담예약이 있으면 예약마다 연결할 내담자를 직접 선택한다. 이름만으로 자동 연결하지 않는다. 선택하지 않은 예약과 지난 예약은 남는다. 한 번에 예약 200건 이하를 처리한다.
5. 사유를 입력하고 ‘미리보기’를 누른다. 중복 등록번호·권한·예약 시간 겹침·자료 버전 검사를 수행한다. 미리보기에는 데이터 변경이 없다.
6. 대상과 새 담당자를 확인하고 확인란에 체크한 뒤 ‘인계 실행’을 누른다. 한 항목이라도 실패하면 전체가 원래대로 유지된다. 같은 요청의 재시도는 중복 인계되지 않는다.

인계는 해당 내담자 레코드의 소유자와 선택한 예약의 담당자를 바꾼다. 지정일·훈련·만료일·참고 메모 등 내담자 payload 원문은 유지한다. 예약의 원 작성자와 인계 전 기록은 보존한다. 개인 할 일·일반 업무 메모·직원 알림기기·개인 캘린더 연결·계정정보를 다른 사람에게 넘기지 않는다.

**중요한 범위:** 현재 서버의 `schedule_private_items(kind=iap)`에 보관된 ‘내담자 일정관리’ 자료와 명시적으로 선택한 향후 상담예약이 대상이다. 각 PC에만 저장된 통합본 상담일지·IAP 원문은 서버에 없으므로 자동 인계되지 않는다. 해당 원문은 기존 암호화 백업 등 별도 인계가 필요하다. 이 기능이 두 프로그램의 모든 자료를 옮긴다고 안내하지 않는다.

## 인계 이력과 취소

원본 스냅샷과 인계 결과를 하나의 DB 트랜잭션으로 비공개 `private.schedule_client_handoff_batches`에 저장한다. 익명 및 일반 인증 사용자의 테이블 직접 접근은 차단한다. 미리보기 계획은 브라우저 영속/세션 저장소에 보관하지 않는다. 로그아웃·계정 변경·15분 무사용 시 화면을 잠그고 개인정보를 비운다.

인계 이력에서 전체 취소가 가능하다. 내담자·예약·생성된 자동완성 자료의 버전/내용과 새 사용 여부를 검사한다. 새 담당자가 수정했거나 원 담당자 쪽에 중복 등록번호가 생겼다면 자동 취소하지 않는다. 취소가 성공해도 퇴사자 계정은 비활성 상태로 유지된다. 원본 스냅샷은 업무상 인계 이력으로 보관되며, 자료별 보존기간 확정 전 자동 파기를 적용하지 않았다.

## 검증

`test.sql`은 반드시 `BEGIN ... ROLLBACK` 안에서 실행한다. 가상 로그인 사용자·직원·내담자·예약만 생성하며 마지막에 모두 롤백한다. 관리자/타센터/일반 직원 권한, 미리보기 비변경, 분할 배정, 중복·동시 수정·예약 충돌, 전체 원자성, 재시도, 수신자 RLS, 퇴사자 차단, 원문/과거 예약/개인 할 일 보존, 변경 없는 취소와 수정 후 취소 거부를 검사했다. 수정 시각을 바꾸지 않고 내용을 수정한 경우도 취소를 거부한다.

DOM 테스트는 실제 화면 코드로 담당자/예약 분할 선택, 확인 전 실행 차단, 계획 변경 시 미리보기 무효화, 성공 후 목록 갱신, 로그아웃 후 늦은 응답 차단과 저장소에 계획이 남지 않음을 검사한다. Chrome PC/모바일 크기 및 로그아웃 검사를 기존 CI 브라우저 검사에 연결했다. 실제 직원 자료의 인계는 별도 업무 실행이며 테스트 중에는 실행하지 않았다.

`schema.sql`은 운영 서버에 이미 반영한 기능 정의다. 프런트 배포 때 자동 재실행할 파일이 아니다. 기능을 사용 중지하려면 우선 public RPC의 authenticated 실행권한을 회수하고 링크를 제거한다. 인계 이력이 있는 테이블을 DROP하거나 직원/내담자 원본을 삭제하지 않는다.

# 내 할 일: 메모, 마감, 선택 알림

- `tasks.html`에서 종류를 메모/할 일로 선택합니다. 메모에는 완료 체크와 마감을 표시하지 않습니다.
- 할 일은 완료 기한을 지정하거나 날짜를 비워 기한 없이 저장할 수 있습니다. 기존 항목의 날짜를 임의로 마감으로 바꾸지 않습니다.
- 일간/주간/월간은 할 일 지정일·마감 기준입니다. 기한 지난 일, 오늘 마감, 7일 이내 마감, 기한 없는 일, 메모, 완료는 전체 개인 기록을 모아 보여줍니다. 지난 미완료 기한은 별도 안내로 계속 표시합니다.
- 알림은 기본 꺼짐입니다. 기기의 할 일 알림을 켠 뒤 원하는 항목에서 알림 여부와 시간을 지정합니다. 시간은 한국시간 기준입니다. 기기 권한과 항목 설정 둘 다 필요합니다. 아이폰은 Safari에서 홈 화면에 추가한 앱으로 사용합니다.
- `task-sw.js`의 별도 서비스워커 등록/구독과 `schedule_task_devices`를 사용합니다. 기존 상담일정 알림 구독과 독립적입니다. 화면이 닫혀 있어도 브라우저 푸시를 사용할 수 있으나 OS·네트워크·절전 정책에 따라 지연될 수 있습니다.
- 매분 `schedule-task-reminders`를 실행합니다. Vault의 기존 내부 스케줄러 인증키를 검증하며, 일반 브라우저는 큐 선점 RPC를 실행할 수 없습니다. 기한/알림 수정, 완료, 메모 전환, 삭제는 트리거로 큐에 반영됩니다.
- 발송 직전 본인 작업과 알림 설정을 다시 확인합니다. 잠금 화면에는 작업 내용 없이 일반 알림만 표시하며, 클릭 후 로그인 계정의 항목을 엽니다.
- 전송 실패는 5분 후 재시도하며 24시간 이상 지난 예약은 발송하지 않습니다. 푸시 서비스 수락은 기기 수신 확인이 아니며 전달 완료의 엄밀한 한 번 보장은 하지 않습니다.

## 배포와 검증

1. `docs/sql/private_task_reminders.sql` 스키마 및 `schedule-task-reminders` Edge Function을 배포합니다. 함수는 `verify_jwt=false`이며 자체 내부키 인증을 수행합니다.
2. `docs/sql/task_reminder_scheduler.sql`로 매분 스케줄을 등록합니다.
3. 순수 모델/서버 모의 발송 테스트와 기존 안전 회귀 테스트를 실행합니다. 실제 DB 트랜잭션에서 소유자 격리, 완료·메모·해제 시 취소, 브라우저 큐 선점 금지를 확인 후 롤백했습니다.
4. 실제 함수의 인증 포함 dry-run 응답 및 cron 실행을 확인합니다. 실기기 권한 승인·알림 표시는 사용자 기기에서 추가 확인이 필요합니다.

## 구현된 코드

- 확장프로그램에 의존하지 않는 공통 내담자 모델, 수동 등록, 등록정보 선택, 자동·수동 출처 및 충돌값 표시.
- 초기·해석·IAP의 연결 필수 안내. 번호 없이 임시 작성은 계속 가능하며, 전산 전송은 번호가 필요하다.
- 기존 화면의 번호 입력 요소/이벤트를 유지하면서 작은 공통 UI로 이동한다. 다른 내담자 번호로 기존 폼을 재명명하는 동작을 차단한다.
- 확장프로그램이 응답하지 않아도 설치 경고를 표시하지 않는다. 작성/출력은 기존 메뉴가 담당한다.
- IAP 번호/공통정보를 인증 직원 이메일별 저장공간으로 분리한다. 구형 공용 키의 원문은 삭제하지 않는다.
- 확장프로그램 1.4.29 **검증용** 소스를 `extension/`에 추가했다. GitHub에 추적 중이던 `releases/work24-helper-1.4.24.zip`에서 복원한 소스가 기준이다. 실제 Chrome Web Store 배포 버전과 동일한지는 미확인이다.
- 통합본에서 요청하면 확장프로그램이 상세 필드만 새로 읽는다. 목록/임의 본문은 번호 증거로 사용하지 않으며, 다중 번호/접근 실패는 연결을 중단한다. 컨텍스트는 확장 저장소에 보관하지 않는다.
- 기존 IAP 입력 전/입력 중 검증 유지. 재진단 설문도 번호를 전달하고 입력 대상 문서를 고정하며, 실제 변경 직전에 번호를 확인한다.
- 일정표는 기존 개인 자료 테이블/RLS 경로를 사용한다. 양쪽 로그인 이메일과 직원 권한을 재확인하고 기존 수정시각으로 충돌을 검사한다. 기존 날짜/훈련/메모를 유지하고 값이 다른 기존 정보는 자동 변경하지 않는다.

- 실제 DB를 읽어 `schedule_private_items`의 RLS 활성화 및 인증된 활성 직원의 본인 user_id 제한과 UPDATE의 USING/WITH CHECK를 확인했다. 데이터/정책 변경은 실행하지 않았다.

## 배포를 막는 미해결 사항

1. **기존 자료 이전의 운영 확인**: 등록번호별로 본인 담당임을 확인하고 이전하는 코드와 취소·소유자 차이·충돌·실패 복구 검사는 완료했다. 실제 직원 브라우저의 원본/백업/이전 결과 대조는 현장 확인이 필요하다.
2. **실제 전산망 검사**: 로그인된 고용전산망/북부센터 Windows PC에 접근하지 못했다. 자동 감지, 실제 상세 필드 별칭, 단일/다중 참여자, 화면 전환 도중 입력 중단을 현장에서 확인해야 한다. DOM 모의 통과를 실제 환경 A 통과로 간주하지 않는다.
3. **브라우저 및 출력 범위**: GitHub CI의 실제 Chrome에서 확장프로그램을 끈 채 15개 메뉴(학교 p21/p23 중첩 프레임 포함)의 수동 연결 저장과 미설치 경고 없음 검사를 통과했다. 기존 전체 브라우저 smoke도 통과했다. 실제 직원 로그인 후 전 메뉴 출력 및 실사용 데이터의 복원/저장은 추가 검증이 필요하다.
4. **일정표 실제 왕복**: 같은 번호의 고정 ID로 동시 신규등록이 중복 생성되지 않는 코드를 구현하고 두 화면 모의 DB 검사에서 확인했다. 동일 계정/다른 계정/다른 센터/로그아웃/동시 수정의 실제 서버 왕복 테스트는 별도로 필요하다.
5. **배포판 소스 확인 및 전체 회귀검사 정리**: 실제 배포 확장 소스와 대조해야 한다. 종료시 기존 DOM 테스트의 타이머 오류 출력도 정리해야 한다.

이 초안은 merge, Pages 배포, 확장프로그램 스토어 업로드 대상이 아니다. 운영 코드와 기존 기록을 변경/삭제하지 않았다.


## 후속 보완 (이번 작업 범위 유지)

- 모든 상담일지 이력 저장 및 21일 계산 변경은 후속 계획으로 제외했다. 기존 상담일 감지 코드는 변경하지 않았다.
- 기존 공용 브라우저 자료는 등록번호 하나씩 본인 담당 자료임을 확인한 경우에만 옮기는 UI를 추가했다. 다른 번호를 열거하지 않는다. 이미 다른 직원에게 연결된 자료/다른 직원 이메일이 적힌 자료/현재 자료와 다른 값은 거부한다. 원본과 복구 사본을 보존하며 저장 실패시 기존 직원별 자료를 되돌린다. 이 확인은 구형 자료의 최초 이전에만 필요하다.
- 엑셀 가져오기의 기존 고정 ID를 수동 신규등록과 통합본 연동에도 사용한다. 대소문자 차이를 정규화하며 DB 기본키로 동시 중복 생성이 차단된다. 충돌한 요청은 덮어쓰기 없이 안내하고 재시도할 수 있다. DB 정책이나 스키마 변경은 필요 없다.
- 자동 연결의 5초 반복 검사를 제거했다. 전산 화면 변경, 탭 전환, 통합본 포커스/메뉴 변경 때 확인한다. 같은 감지 결과는 반복 저장하지 않고 내담자 선택 목록도 데이터가 바뀔 때만 재구성한다.
- 일반 상담 14개 메뉴와 학교 중첩 화면 2개를 포함하는 Chrome 검사로 확장했다.
- 확인 가능한 최신 보관 소스 1.4.28의 IAP 입력번호 검증을 합쳤다. 부모/별도 목록의 번호가 실제 IAP 상세번호를 오염시키지 않도록 하고, 입력 직전에도 재확인한다. 10,001개 DOM 요소 fixture에서 검사당 스타일 읽기 3회/레이아웃 읽기 1회인 기존 성능 검사를 재사용해 통과했다. 실제 PC 속도 측정은 아니다.
- 신규 검사: 기존 자료 이전/취소/중복/소유자 차이/원문 보존/쓰기 실패 복구, 실제 두 화면의 동시 연동 요청/중복 재시도/계정 차이/처리 중 로그아웃 (DB는 모의 환경).

이 보완으로 위의 **코드 미구현이던 기존 자료 이전과 동시 신규등록 방지 항목은 해결**했다. 실제 배포 확장 버전 확인, 고용전산망 현장 검사, 로그인된 운영 직원의 저장·복원·출력 및 실제 일정표 서버 왕복 검사는 여전히 남아 있다. 운영 배포는 보류한다.

- 따라서 앞에서 남아 있던 **배포판 소스 확인**은 완료했다. 실제 직원 PC 고용전산망의 자동 감지/충돌 차단/입력, 실제 일정표 서버 왕복 및 본인 브라우저의 구형 자료 이전·복원·출력 검증은 아직 미완료다. 자동·모의 검사를 현장 검사로 간주하지 않는다.
- 이 작업의 운영 배포/병합/스토어 업로드/운영 DB 변경은 실행하지 않았다. 원본 기록 삭제 없음. 상담 이력·21일 계산 공통 연동은 다음 단계 계획으로 유지한다.

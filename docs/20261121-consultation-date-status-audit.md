
# 상담일 이력 · 21일 확인 · 중요 날짜 변경 / 상태 연동 (검증용)

2026-11-21. **운영 배포 전 검증용**. 상담일지 통합본 `my-html-4`의 동명 작업 브랜치와 세트입니다.

## 데이터 구조

- `schedule_private_items`는 기존대로 `iap`·`todo`만 저장합니다. 내담자 날짜·훈련·상태의 기존 자료를 임의로 삭제/초기화하지 않습니다.
- **새 테이블** `schedule_client_activity`에 실제 상담일과 날짜·상태 변경의 최소 이력만 저장합니다. 상담 전문·주민등록번호·연락처는 기록하지 않습니다.
- 활동 이력은 직원 인증/RLS, 본인 소유의 `iap` 기록 `client_id` FK 및 일치하는 IAP 번호를 확인한 경우에만 추가 가능합니다. SELECT/INSERT만 허용하며 UPDATE/DELETE는 허용하지 않습니다. 내담자 일정 원본을 삭제하면 해당 이력은 FK CASCADE로 같이 삭제됩니다.
- DB 적용 전에는 새 이력 기능이 동작하지 않습니다. 기존 일정 화면은 이력 데이터를 불러오지 못해도 보호되어야 하며, 이력 미조회와 상담 미실시를 혼동하지 않습니다.

## 21일 내부 점검 규칙

- 상담일지에서 상담사가 직접 **실제 상담 실시**를 체크하고 확정한 날짜만 기준으로 합니다. 초안·검색·저장 버튼·IAP 수립 예정일만으로 상담을 실시했다고 판단하지 않습니다.
- **마지막 실제 상담일부터 달력일 21일 이상** 경과한 참여 중 내담자만 내부 점검 대상입니다. 법정 의무상담 시점이나 수당 지급·유예·중단 판단이 아닙니다.
- 상담이력 미등록은 ‘상담일 미등록’으로 별도 표시하며 21일 경과자로 단정하지 않습니다. 취업·일시 중지·종료 상태는 점검 대상에서 제외합니다.
- 상담 이력은 저장 건별 `source_key`로 중복 전송 시 추가되지 않습니다. 서로 다른 탭/상담 메뉴의 같은 날짜 이력은 별도 기록됩니다.

## 날짜·상태 변경 규칙

- 수동으로 입력한 지정일·재진단일·훈련일정은 공식 IAP 자료와 다른 경우 덮어쓰지 않습니다.
- 날짜 변경은 이전/이후 값을 본인 이력으로 기록합니다. 기존 `changeHistory`를 보존하며 이력 테이블의 추가 저장이 실패하면 **일정 저장 성공과 이력 기록 실패를 구분**하여 안내합니다.
- 참여상태 변경은 상담일지의 별도 상태 선택 + 적용일 + 사유 + 명시적 체크가 있어야 합니다. 상담 원문에서 '취업' 등을 찾아 자동으로 상태 처리하지 않습니다.
- 기존 내담자 연결이 확인되지 않거나 직원 계정·센터가 일치하지 않으면 상담일/상태 연결을 중단합니다. 공식 고용24 전산 상태를 변경하지 않습니다.

## 배포 전 필수 사항

1. 두 저장소의 작업 브랜치/PR을 **같이** 검증하고, 기존 파일·브라우저 기록 백업과 필요 시 복원을 확인합니다.
2. `supabase/migrations/20261121_schedule_client_activity.sql`의 SQL/RLS를 검토한 후 인증 직원의 데이터가 없는 테스트 환경에서 DDL과 정책을 실행·확인합니다.
3. 이후 승인된 서버에 마이그레이션을 적용하고 테이블 SELECT/INSERT 전용 접근, 다른 계정 읽기/쓰기 불가, 삭제 시 FK CASCADE를 테스트합니다.
4. 테스트용 IAP 저장→신규 등록→실제 상담 날짜 기록→21일 요약→날짜 변경→상태 확인→동일 저장 재시도·로그아웃을 실제 직원 계정/Chrome에서 검증합니다.
5. 상담사관리 엑셀, 실제 상담 예약, 구촉수당 전산자료, 고용24 전산상태, 자동 21일 법정 판단에는 영향이 없습니다.

**운영 DB 데이터와 기존 IAP·상담 기록을 임의로 변경하지 않습니다.** 실제 서버 왕복 테스트 없이 완전 연동이라고 안내하지 마세요.
